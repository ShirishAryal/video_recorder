Flutter plugin · Android & iOS 15+

video_recorder

A full-screen recorder that hands your app a finished, upload-ready video file, and a player for watching it back from disk or a URL.

final video = await VideoRecorder.record(context,
  options: const VideoRecorderOptions(
    hints: ['Introduce yourself', 'Describe the problem'],
    maxDuration: Duration(seconds: 60),
    convertToHevc: true,
  ));
if (video != null) upload(video); // your app owns the file

RecordedVideoPlayer.network(Uri.parse(url), autoPlay: true);

Features

Recording

  • Record, Stop, Pause / Resume, Restart
  • Switch front and back camera
  • 3-2-1 countdown before recording
  • Time limit with a filling ring and countdown
  • Hints to read while speaking, with Previous / Next
  • 720p by default; every button has a text label

Review

  • Take plays once, with a scrubbable bar
  • Replay when it ends
  • Re-record discards the take
  • Save returns the file to the app

Output

  • Compact bitrates per quality (about 19 MB/min at 720p)
  • Optional on-device HEVC: about 40% smaller
  • Streaming-ready MP4: index moved to the front
  • Always falls back to a working file

Playback

  • RecordedVideoPlayer for files and URLs
  • HTTP headers for authenticated videos
  • Buffering spinner, Retry on failure
  • Preloads the next videos in a feed
  • Fits its box; portrait or landscape

Architecture

Four public entry points (plus VideoPreloader, which feeds open videos to the player) sit on top of three foundations: the camera plugin for capture, video_player for playback, and the package's own native plugin, reached through Pigeon, for HEVC conversion. Making files streamable is pure Dart, so it needs no native code.

Dart in this package Flutter plugins it depends on Native frameworks Save calls the converter and rewriter

Recorder screen states

VideoRecorderScreen is a single state machine. Each state shows its own buttons, so the controls can never get into an impossible combination, such as switching cameras mid-recording.

Save pipeline

Tapping Save runs up to two optional steps before the route closes. Each step can only make the file better: if a step can't help, the previous file passes through unchanged. Intermediate files are deleted, so exactly one file reaches your app.

Native bridge

HEVC conversion is the only feature with code of its own on each platform. The API is defined once in pigeons/messages.dart; Pigeon generates type-safe Dart, Kotlin and Swift from it, so a misspelt field is a compile error rather than a runtime surprise.

Default bitrates

Phones record at around 10–15 Mbps by default. The package records at rates chosen for someone talking to the camera, and every value can be overridden.

Known limits

Not yet tried on physical phones. Everything above ran on simulators and emulators. iPhone camera recordings in particular haven't been recorded for real, because the simulator has no camera.
HEVC playback. HEVC files play on iOS, macOS, Safari and almost all Android phones, but not in every desktop browser. That's why convertToHevc is off by default.
Bitrates are targets. Phones may round them, and some Android devices enforce a minimum bitrate.
Web. Recording and playback work through the plugins, but HEVC conversion and the streamable rewrite are skipped and return the original file.
Preloading uses data. A paused, preloaded video keeps downloading as far as the platform player decides: in a test with a 60-second, 19 MB clip, about 19 MB on Android and the whole file on iOS. Keep feed clips short and maxIdle small on mobile data.
